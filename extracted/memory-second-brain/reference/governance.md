# Governance

Memory is a governed resource. The engine may propose; only a human disposes.

## The gate

Every operation that changes a memory's authoritative state passes through a review item
and an approval event.

| Operation | Queued as | On approval |
|---|---|---|
| Apply a contradiction resolution | `CONTRADICTION` | `CONTRADICTION_RESOLVED` + status events |
| Merge a probable/possible duplicate | `PROBABLE_DUPLICATE` / `POSSIBLE_DUPLICATE` | `MERGE_APPLIED` + `duplicate_of` link |
| Consolidate several memories | (consolidation item) | `CONSOLIDATION_CREATED` + `derived_from` links |
| Supersede a memory | (supersession item) | `MEMORY_SUPERSEDED` + `superseded_by` link |
| Retract a memory | (retraction item) | `MEMORY_RETRACTED` — terminal, never reversed |
| Release a quarantine | `QUARANTINE_RELEASE` | `MEMORY_STATUS_CHANGED` → the new status |
| Change status for any other reason | `LOW_CONFIDENCE` or explicit item | `MEMORY_STATUS_CHANGED` |

Auto-apply is available **only** for `EXACT_DUPLICATE` merges, because the content is
byte-identical and the merge is information-preserving. Everything else waits.

## Approval event

```python
approval = {
    "v": 1,
    "review_item_id": item_id,
    "decision": "APPROVED" | "REJECTED" | "DEFERRED",
    "rationale": rationale,
    "claimed_authority": claimed_authority,   # e.g. "OWNER", "COUNCIL", "NONE"
    "actor": actor,
    "created_at": created_at,
}
approval_hash = digest(DOMAIN_APPROVAL, approval)
```

`claimed_authority` is recorded **as claimed**. The identity layer that validates the claim
is a separate system; memory records the claim faithfully and the chain makes it auditable.

## Authority discipline

| Concept | Rule |
|---|---|
| Advisory vs authoritative | An inference layer (shadow, twin, planner) may *propose*. Only an approval event *disposes*. |
| No self-approval by inference | A proposal generated by an inference-layer actor cannot be approved by the same actor id. |
| Retraction is terminal | `RETRACTED` is never left. A retracted memory stays queryable and stays retracted. |
| Quarantine beats absorption | Ambiguous, unsafe, or unverified input goes to `QUARANTINED`, not into the active store. |
| Review queue is exhaustive | Nothing that needs a decision may be absent from it. An empty queue must mean "nothing pending", never "nothing surfaced". |

## Audit

Three audit questions must be answerable at any time, from the ledger alone:

1. **What is true now?** — replay the ledger to the head, read statuses.
2. **Why is it true?** — walk `derived_from`, `superseded_by`, `supports`, and the approval
   event; the `explain` verb returns exactly this.
3. **Who decided?** — the `actor` and `claimed_authority` on every state-changing event.

If any of the three requires data outside the ledger, the design is wrong — the missing
data belongs in an event payload.

## What the governance layer must never do

- Auto-resolve a contradiction, even when the factors are lopsided.
- Drop or auto-expire an open review item into a resolution.
- Let a retrieval path mutate state.
- Accept an unverified `import_snapshot` into a non-empty store.
- Allow a bulk "migration" to rewrite historical rows — the append-only triggers will
  abort it, and that abort is the correct outcome.
